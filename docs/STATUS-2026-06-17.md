# Project Status — 2026-06-17

Summary

LukaScope is a functional prototype for AI-assisted blood smear analysis with a web-based UI and a Python backend. The system supports image uploads, background processing (job queue), generation of visual artefacts (heatmaps), review workflows, and an AI training workspace for dataset preparation and model training.

How it is used

- Clinicians or lab technicians upload blood-smear images via the web UI.
- The backend enqueues analysis jobs which are processed by Redis/RQ workers.
- Workers generate heatmaps and produce a structured result saved to the database and file storage.
- Results are presented to the user in a paginated results view; each sample has a detailed view with heatmaps and metadata.

Expected user experience (MVP)

- Simple login screen (static credential check for the MVP).
- Dashboard for uploading images, viewing job progress and project summary.
- Results grid with pagination and a single-result detail page including heatmaps and metadata.
- Ability to mark reviews/labels to curate a reviewed dataset for retraining.

Current tech stack

- Frontend: Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS v4, shadcn/ui
- Backend: FastAPI (Python 3.11+), SQLAlchemy models, Redis + RQ for background tasks
- AI / Training: Python workspace using PyTorch, Ultralytics YOLO, torchvision, OpenCV, Albumentations
- Local data store: File-backed uploads & artefacts; SQLite by default (Postgres supported via DATABASE_URL)
- Dev tooling: Bun for frontend workspace, Docker Compose for containerised runs

Planned / future tech

- Replace local file storage with an object store (S3-compatible) for scalability and easier deployment.
- Migrate to Postgres in production and add database migrations (Alembic).
- Add authentication/authorisation (e.g., OAuth2 / OpenID Connect) and audit logging for clinical use.
- Improve model serving (TorchServe, BentoML or FastAPI model endpoints) for lower-latency inference.
- CI/CD with tests running on PRs, container scanning, and automated model evaluation pipelines.

Immediate next steps (recommended)

1. Implement persistent storage for models and uploads (S3) and move away from local-only file storage. (Medium effort)
2. Add role-based authentication and secure the API endpoints for clinical deployment. (Medium–high effort)
3. Add database migrations and switch to Postgres for staging/production. (Low–medium effort)
4. Harden the worker queue (monitoring, retry policies, backoff) and add observability (metrics + logs). (Low–medium effort)
5. Create a minimal CI pipeline to run linting and tests on PRs. (Low effort)

Known limitations

- Not production hardened: authentication, input validation, rate limiting and audit logging are minimal or missing.
- Local file storage will not scale; backups and concurrency may be problematic in multi-instance deployments.
- Clinical validation and regulatory compliance are not covered — this prototype is for research and development (R&D) only.
